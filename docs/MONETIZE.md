# 수익화 가이드

아이디어 #7의 핵심은 이렇습니다. **한 번 만들어 올려 두면 결제될 때마다 자동으로 발송되고, 재고와 배송이 없습니다.**
처음 팔리기까지 몇 주가 걸리고, 잘 팔리는 템플릿 1~2개가 매출 대부분을 차지합니다. **직접 써서 효과를 본 템플릿**부터 시작하세요.

> 첫 단계: 지금 쓰고 있는 양식 중 남이 써도 쓸모 있을 것 하나를 고릅니다. 이 앱의 가계부·업무 관리표·여행 플래너로 몇 주 직접 써 보고, 불편했던 점을 고친 버전을 상품으로 만듭니다.

---

## A. 판매용 엑셀 양식 팔기 (지금 바로 가능)

1. 앱에서 템플릿 문서를 열고 `⋯ → 빈 엑셀 양식 만들기(판매용)`을 누릅니다.
   - 포함되는 것: **사용 안내** 시트, 머리글 서식, 틀 고정, 필터, **드롭다운**(분류·상태 등), **자동계산 수식**(합계, 예산 대비 사용액, D-Day, 월 환산 금액), 미리 서식을 넣은 200행
2. 엑셀에서 열어 확인하고, 예시 데이터를 채운 화면을 캡처해 **상세페이지 이미지**로 씁니다. 앱의 `엑셀(.xlsx)로 저장`을 쓰면 예시 데이터가 들어간 파일이 나옵니다.
3. 판매 플랫폼에 등록합니다.
   - **크몽**: 전자책·템플릿 카테고리에 파일을 첨부합니다.
   - **스마트스토어**: 디지털 상품으로 등록하고 다운로드 파일을 첨부합니다.
   - **Gumroad**: 상품 → Content에 파일을 첨부합니다. 결제 즉시 다운로드 링크가 발송됩니다.
4. 팁
   - 상품명에는 검색어를 넣습니다. 예: “자동계산 가계부 엑셀 양식 | 예산·분류별 지출 그래프”
   - 같은 템플릿을 “기본 / 확장” 두 가지 가격으로 나누면 객단가를 올리기 좋습니다.
   - 구매자 후기와 질문을 보고 템플릿을 개선한 뒤 `npm run bump`로 앱에도 반영합니다.

## B. 앱 프리미엄 라이선스 팔기

프리미엄 템플릿(`premium: true`)은 라이선스 코드로 엽니다. 코드는 **전자서명**이 들어가 있어 위조할 수 없고, 서버 없이 앱 안에서 확인합니다.
등록한 코드는 로그인한 계정에 저장되어 그 계정의 PC와 휴대폰 모두에 적용됩니다.

### 1) 서명키 만들기 (최초 한 번)
```bash
npm run license:keygen
```
- `.secrets/license-private.jwk.json`: **개인키**입니다. 절대 공유하거나 커밋하지 마세요(`.gitignore` 처리됨). USB나 비밀번호 관리자 같은 곳에 **따로 백업**하세요. 잃어버리면 새 코드를 발급할 수 없습니다.
- `app/js/license-key.js`: **공개키**가 자동으로 기록됩니다. 이 파일은 커밋합니다.
- 이후 `npm run bump -- minor "프리미엄 판매 시작"` → push

### 2) 구매 링크 연결
`app/js/config.js`
```js
purchaseUrl: 'https://kmong.com/...',   // 또는 스마트스토어 / Gumroad 상품 주소
priceText: '프리미엄 9,900원 · 한 번 구매로 평생 사용',
```

### 3) 코드 발급
```bash
npm run license:issue -- --count 100              # 모든 프리미엄 템플릿을 여는 코드
npm run license:issue -- --count 20 --plan habit  # 특정 템플릿(id)만 여는 코드
```
`.secrets/issued/licenses-*.csv`에 코드가 저장됩니다. 코드는 `TK1.`로 시작하는 약 125자 문자열입니다.

### 4) 자동 발송 연결
- 구매자마다 다른 코드를 자동으로 보내 주는 기능이 플랫폼에 있으면 CSV의 코드 목록을 등록합니다.
- 그런 기능이 없으면 이렇게 합니다.
  - 자동 발송 파일(안내 PDF·텍스트)에 **이번 판매 회차의 공용 코드**를 넣고 주기적으로 새 코드로 바꾸거나,
  - 결제 알림을 받으면 코드 한 줄을 메시지로 보냅니다. 하루 1~2분이면 됩니다.
- 구매자 안내 문구 예시: “앱 → 설정 → 프리미엄 → 코드 붙여넣기 → 코드 등록”

### 알아둘 점
- 코드 하나를 여러 사람이 나눠 쓰는 것까지는 막지 못합니다. 초기 판매 단계에서는 충분하지만, 규모가 커지면 서버에서 확인하거나 인앱 결제로 바꿉니다.
- 개인키를 다시 만들면(`--force`) 이미 판 코드가 **모두 무효**가 됩니다.

## C. 스토어 앱 결제 (모바일 앱 출시 후)

- **App Store(iOS)**: 앱 안에서 기능을 여는 디지털 상품은 **Apple 인앱 결제**를 써야 합니다(App Review Guideline 3.1.1). 외부에서 산 코드로 앱 기능을 여는 방식은 심사에서 거절될 수 있으니, iOS 빌드에서는 라이선스 입력 대신 인앱 결제를 붙입니다.
- **Google Play**: 앱 안에서 파는 디지털 상품은 원칙적으로 Play 결제 시스템을 씁니다(국가별 예외·대체 결제 규정은 출시 시점의 정책을 확인하세요).
- 구현 방법: RevenueCat 같은 Capacitor 인앱 결제 플러그인으로 구매가 확인되면, 그 계정에 `premium`을 기록하는 식으로 지금 구조에 연결합니다(`app.plans`에 플랜을 추가하는 부분).
- 웹/PC 버전은 지금처럼 라이선스 코드로 판매를 계속할 수 있습니다.
