# 템플릿킷 (TemplateKit)

> 삶의 질 개선 아이디어 **#7 디지털 템플릿 자동 판매**를 실제로 굴리기 위한 프로그램입니다.
> 직접 써서 효과를 본 템플릿(가계부·업무 관리표·여행 플래너…)을 **앱**으로 쓰고, 같은 템플릿을 **판매용 엑셀 양식**으로 뽑아 팔 수 있습니다.

수익 경로는 두 가지입니다.

1. **판매용 엑셀 양식** — 앱의 `⋯ → 빈 엑셀 양식 만들기(판매용)`이 안내 시트, 드롭다운, 자동계산 수식이 들어간 `.xlsx` 파일을 만들어 줍니다. 이 파일을 크몽·스마트스토어 디지털 상품·Gumroad에 올리고 자동 발송을 켜 두면, 결제될 때마다 파일이 자동으로 나갑니다.
2. **앱 프리미엄** — 무료 템플릿 3종은 그냥 쓰게 두고, 프리미엄 템플릿(습관 트래커, 구독 관리 등)은 **라이선스 코드**로 엽니다. 코드 목록을 판매 플랫폼의 자동 발송에 등록해 두면 재고도 배송도 없습니다. 나중에는 이 앱을 그대로 Play 스토어·앱 스토어에 올립니다.

## 요구사항별 구현 내용

| 요구사항 | 구현 |
| --- | --- |
| **재설치 없이 업데이터로 개선** | 웹/설치형(PWA)에서는 서비스 워커가 새 버전을 백그라운드에서 미리 받습니다. 앱을 막 연 상태면 바로 적용하고, 쓰는 중이면 “새 버전 준비됨 → 지금 업데이트” 배너를 띄웁니다. 스토어 앱(Capacitor)은 같은 서버에서 새 웹 번들(zip)을 받아 교체합니다(`app/js/updater.js`). `설정 → 업데이트`에서 직접 확인할 수도 있고, 업데이트 내역도 보여 줍니다. |
| **아이콘 더블클릭으로 실행** | PC(Chrome·Edge)에서 `설정 → 앱 설치`를 누르면 바탕화면과 시작 메뉴에 아이콘이 생기고, 더블클릭하면 별도 창으로 열립니다. 설치 기능을 못 쓰는 환경을 위해 `launcher/` 폴더에 더블클릭용 실행 파일(.bat / .command)도 넣어 두었습니다. |
| **모바일 폰에서 실행** | 휴대폰 화면에서는 표가 카드 형태로 바뀝니다. Android는 “앱 설치”, iPhone은 Safari의 “홈 화면에 추가”로 아이콘을 만들 수 있습니다. 오프라인에서도 동작합니다. |
| **같은 계정이면 PC·모바일 연동** | Firebase 로그인(이메일 또는 Google)과 Firestore 실시간 동기화를 씁니다. 문서와 프리미엄 등록 상태가 모든 기기에 반영됩니다. 오프라인에서 수정한 내용은 다시 연결될 때 자동으로 올라가고, 충돌이 나면 마지막에 수정한 쪽이 남습니다. |
| **최종 목표: 모바일 앱 배포·수익화** | 같은 코드를 Capacitor로 감싸 Android·iOS 앱으로 만듭니다. 설정 파일(`capacitor.config.json`)과 스토어 앱 업데이트 경로(`@capgo/capacitor-updater`)를 미리 준비해 두었습니다. → [docs/MOBILE_APP.md](docs/MOBILE_APP.md) |

## 기능

- 템플릿: **가계부**(내역, 예산 대비 사용액), **업무 관리표**(D-Day, 지연 업무, 완료율), **여행 플래너**(일정, 준비물, 경비). 프리미엄: **습관 트래커**, **구독 관리**
- 월별 보기, 검색, 열 정렬, 요약 카드, 분류별 막대그래프
- 엑셀(.xlsx) 내보내기(합계와 계산 수식 포함), CSV 내보내기, **판매용 빈 엑셀 양식** 만들기
- JSON 백업과 복원, 다크 모드, 오프라인 실행

## 빠른 시작 (내 PC에서 확인)

```bash
npm start          # http://localhost:5173  (Node.js 20 이상, 설치할 패키지 없음)
npm test           # 자동 테스트
```

## 배포 (무료, GitHub Pages)

1. 이 저장소의 작업 브랜치를 `main`에 병합합니다.
2. GitHub 저장소 → **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택합니다. 무료 계정은 저장소가 Public이어야 합니다.
3. `main`에 push하면 `.github/workflows/deploy.yml`이 테스트를 돌린 뒤 `https://tlsgusdlf33.github.io/A13/`에 배포합니다.
4. 주소가 다르면 `app/js/config.js`의 `appUrl`과 `launcher/` 파일들의 URL을 고칩니다.

## 설치 방법 (사용자 안내용)

- **PC (Windows/Mac)**: Chrome 또는 Edge로 접속 → 주소창 오른쪽 설치 아이콘(또는 앱의 `설정 → 앱 설치`) → 바탕화면 아이콘을 **더블클릭**해서 실행
- **Android**: Chrome으로 접속 → “앱 설치” 또는 메뉴 → “홈 화면에 추가”
- **iPhone**: Safari로 접속 → 공유 버튼 → “홈 화면에 추가”

## 새 버전 내보내기 (업데이트 배포)

```bash
npm run bump -- patch "가계부 검색 개선" "버그 수정"   # 버전과 업데이트 내역을 한 번에 올림
git commit -am "v1.0.1" && git push                    # main에 반영되면 자동 배포
```

이미 설치된 PC·휴대폰 앱은 다음에 열 때(또는 30분마다 확인할 때) 새 버전을 받아 적용합니다. 사용자는 아무것도 다시 설치하지 않습니다. 자세한 내용은 [docs/RELEASE.md](docs/RELEASE.md)를 보세요.

## 폴더 구조

```
app/                      ← 배포되는 앱 전체 (빌드 과정 없음)
  index.html, manifest.webmanifest, sw.js(오프라인+업데이터), version.json(버전·업데이트 내역)
  js/config.js            ← 배포 전에 고칠 설정 (주소, 구매 링크, Firebase)
  js/templates.js         ← 템플릿 정의 (여기에 새 템플릿 추가)
  js/engine.js            ← 템플릿 해석 (필터·정렬·요약)
  js/store.js, merge.js   ← 로컬 저장, 동기화 충돌 해결
  js/sync.js              ← Firebase 로그인과 실시간 동기화
  js/updater.js           ← 업데이터 (웹 / 스토어 앱)
  js/xlsx.js, zip.js, export.js ← 엑셀·CSV 생성 (외부 라이브러리 없음)
  js/license.js           ← 라이선스 코드 검증 (전자서명)
  js/views/               ← 화면 (홈, 문서, 설정)
scripts/                  ← 로컬 서버, 버전 올리기, 라이선스 키·코드 발급, 아이콘 생성
launcher/                 ← 더블클릭 실행기 (Windows / Mac)
tests/                    ← 자동 테스트 (npm test)
capacitor.config.json     ← 모바일 앱 설정
firestore.rules           ← Firestore 보안 규칙 (내 데이터는 나만 접근)
```

## 템플릿 추가하기

`app/js/templates.js`에 객체 하나를 추가하면 화면, 요약, 엑셀 내보내기가 자동으로 붙습니다. 계산 열은 앱용 계산 함수(`compute`)와 엑셀 수식 함수(`excel`)를 함께 정의합니다. 프리미엄으로 팔 템플릿에는 `premium: true`를 넣습니다. 그다음 `npm test`로 확인하고 `npm run bump -- minor "새 템플릿: ○○"` 후 배포하면, 모든 사용자 앱에 새 템플릿이 나타납니다.

## 알아둘 점

- 동기화를 설정하기 전에는 데이터가 **그 기기의 브라우저에만** 저장됩니다. `설정 → 데이터 → 백업 파일 저장`을 가끔 해 두세요.
- 라이선스 확인은 서버 없이 앱 안에서 합니다. 전자서명이라 코드를 위조할 수는 없지만, 코드 하나를 여러 명이 나눠 쓰는 것까지 막지는 못합니다. 스토어 앱에서는 인앱 결제로 바꾸는 것을 권장합니다(MONETIZE.md 참고).
